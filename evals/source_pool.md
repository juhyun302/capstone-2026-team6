# 원문 후보 풀

> 원문은 평가원 공개 문항만 쓴다([README 5절](README.md#5-원문-출처)). 정답은 평가원 정답표에서, 해설은 라벨링 때 팀이 작성한다. `용도`는 선별 메모이며 라벨을 대신하지 않는다.

## 2. dev 원문 — 스파이크에서 사용

| 원문 | 사용처 | 기존 판정 | eval 사용 |
|---|---|---|---|
| 2027-09-common-11 | [후보 품질 스파이크](../docs/spikes/candidate_quality.md) 3번 | 단순 숫자 변경으로 불통과(1인) | `ext-` dev, `rev-` SEED |
| 2027-09-common-12 | 같은 스파이크 2번 | 통과(1인) | `ext-` dev, `rev-` SEED |
| 2027-09-common-13 | 같은 스파이크 1번 | 통과(1인) | `ext-` dev, `rev-` SEED |
| 출처 미기록 · 공통 14 | 같은 스파이크 4번 | 통과(1인), 재생성한 후보 | 출처 확인 전 제외 |
| 출처 미기록 · 공통 22 | 같은 스파이크 5번 | 보류 | 제외 |

- 공통 11·12·13번은 원문 이미지에 "2027학년도 9월"이 적혀 있다.
- 공통 14·22번 이미지에는 시험명이 없고, 22번은 2027학년도 9월 22번과 내용이 다르다. [실행 기록](../docs/spikes/evidence/candidate_quality_run.md)에는 "사용자가 제공한 이미지"로만 적혀 있다. 출처를 확인해 평가원 문항이면 ID를 붙이고, 아니면 공개 저장소에서 이미지를 내리는 것을 검토한다.
- [Artist 재실험](../docs/spikes/artist_calculus_retest.md)의 A1(공비 −1 경계 누락)은 AC4 후보지만 원문이 상업 교재라 이 세트에 넣지 않는다. 같은 결함 유형을 평가원 원문으로 다시 만든다.
