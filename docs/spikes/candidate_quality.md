# 원문 기반 후보 문항의 최종 품질

## 1. 가장 위험한 가정

**원본문항·해설만 받은 Codex가 핵심 풀이 요소 두 개와 연결 메커니즘을 스스로 서술하고, 독립 검토자가 수학적으로 성립하며 사용할 수 있다고 판정하는 후보 문항·풀이를 생성할 수 있다.**

- 실패 영향: 이 가정이 틀리면 [SPEC.md](../SPEC.md)의 후보 생성 기능을 실제 문항 제작에 쓰기 어렵고, 생성된 문제를 사람이 다시 설계해야 한다.
- 근거 부족: 예비 문항 한 건의 자체 검산만으로는 최종 문항의 사람 평가 결과를 알 수 없었다. 이번에 후보 다섯 건을 생성하고 사용자 한 명으로부터 건별 의견을 받았지만, 건별 판정 조건에 대한 구체적 근거는 모두 기록되지 않았다.
- 대체 비용: 템플릿 제작이나 사람이 직접 문항을 만드는 방식으로 바꾸면 원문 유형별 설계·검수 작업이 늘어난다.
- 다른 위험과 비교: 이미지 판독과 원문 메커니즘의 정확한 계승도 검증해야 한다. 이 스파이크는 먼저 판독을 확인한 입력에서 나온 **최종 후보의 품질**을 측정한다. 두 요소의 추출·계승 여부는 모델 출력과 원본 비교 의견에 기록하지만, 후보 품질 통과 건수로 검증됐다고 주장하지 않는다.

## 2. 시간 제한

- 문제당 시간 제한: `3분`, 사람 검토까지 포함한 전체 실험 시간 상한 `1시간`. 이 시간이 모델 생성만을 뜻하는지, 입력 확인·사람 검토까지 포함하는지는 정식 실행 전에 팀이 확정한다. API 예산은 별도 상한을 두지 않는다.
- 종료 조건: 평가 5건을 모두 처리하거나 전체 시간 상한에 먼저 도달하면 중단한다. 남은 사례가 있어도 그 시점의 결과와 미평가 건수를 그대로 기록한다.

## 3. 성공 조건 (실험 전에 확정)

**검증 가능한 문장:** 프롬프트 작성에 쓰지 않은 원본문항 `5건`에서 후보를 하나씩 만들고, 검토자가 아래의 건별 판정 규칙에 맞다고 판단한 후보가 `3건 이상`이면 최종 문항 생성의 기술적 가능성을 인정한다. 이는 원문 메커니즘 계승의 검증을 뜻하지 않는다.

**사람 평가 전 자료 구성 변경:** 검토자가 비교할 수 있도록 원본 문항을 각 생성 문항의 바로 앞 페이지에 배치했다. 처음 기재한 후보만 보는 방식에서 원본·후보를 함께 보는 방식으로 바뀌었으므로, 원본 노출이 후보 품질 판정에 영향을 줄 가능성을 결과 해석에 반영한다.

- 평가 단위: 원본문항·해설 1건 → 후보 문항·풀이 1건.
- 건별 판정 규칙: 검토자에게 원본 문항과 **완성된 후보 문항·해설**을 함께 보여준다. 후보에 대해 ① 조건과 정답이 수학적으로 성립하고, ② 해설의 풀이·정답이 문항과 일치하며, ③ 필요한 조건과 풀이가 갖춰져 실제 문항으로 검토할 수 있고, ④ 원문의 수치·기호만 바꾼 문항이 아니라고 판단할 때만 통과로 센다. 하나라도 충족하지 못하면 불통과다. 핵심 요소 두 개와 연결 메커니즘의 실제 계승 여부는 별도 비교 의견으로 기록하며, 이번 `3/5` 결과만으로 검증됐다고 주장하지 않는다.
- 정식 평가에 넣을 5건은 **모델 출력 전에** 원문·해설의 판독 가능성과 두 요소를 논할 수 있는지를 확인한다. 그 내용은 모델에 전달하지 않는다. 선정된 입력에 모델이 `QUESTION_ERROR`를 반환하거나 후보를 만들지 못하면 불통과로 센다. 사전에 제외한 입력은 제외 이유를 기록하고 다른 새 원문으로 대체한다.

## 4. 방법 (성공 조건을 재는 데 필요한 것만)

1. **평가 자료 준비:** 원본문항·해설 5건을 준비한다. 입력의 수식과 해설이 읽을 수 있고 서로 모순되지 않는지 확인한다. 사람이 추출한 핵심 요소나 연결 메커니즘은 모델 입력으로 제공하지 않는다. 검토자에게 적용할 3절의 판정 예시는 사람 판정 전에 확정한다.
2. **모델 출력 만들기:** 원문·해설의 확인된 내용만 Codex에 주고, 모델이 스스로 핵심 요소 두 개와 연결 메커니즘을 적은 뒤 후보 문항·풀이·두 요소의 응용 근거를 **원문당 한 번** 생성하게 한다. 이 실행의 고정 지시문, 사용 가능한 모델 정보, 출력은 [실행 기록](evidence/candidate_quality_run.md)에 남긴다. 이미지의 수식 판독은 원문 이미지와 대조한다.
3. **사람 판정과 대조:** 검토자에게는 원본 문항을 각 후보 앞에 놓은 [인쇄용 PDF 검토 자료](evidence/candidate_quality_review_packet.pdf)를 준다. 모델의 요소 분석은 가린다. 3절의 건별 판정 규칙에 따라 판단하고, 원본과의 비교 의견은 별도로 적는다. 모델의 요소 분석과 응용 근거는 추후 원문 계승 검증을 위해 별도로 보관하며, 이번 통과 건수의 근거로 사용하지 않는다. 개발자 1차 검토와 강사 2차 사용 승인은 [SPEC.md](../SPEC.md)의 제품 검수 절차로 이어지며, AI의 잠정 검토를 최종 승인으로 취급하지 않는다.

## 5. 결과

2026-09-25에 원본과 생성 문항을 비교했다. 1·2번을 통과, 3번을 단순한 수치 변경으로 불통과, 4번을 원문 오독 뒤 다시 만든 후보라 일회 생성 기준에서 불통과, 5번을 품질 부족으로 보류했다. 3·4·5번은 통과 건수에 넣지 않았다.

| 항목 | 값 |
|---|---|
| 평가 건수 | 원문 5건에서 만든 후보 5건 |
| 통과 | **2건(40%)** — 1·2번 |
| 불통과·보류(통과 미산입) | 3건(60%) — 3·4·5번 |
| 수치 합격선 | 5건 중 3건 이상(60%) |
| 이번 1인 검토 판정 | **2/5로 수치 합격선 미달.** |
| 4번 | 원문의 점 E 정의를 잘못 읽은 최초 초안을 폐기하고 다시 만든 후보다. 다시 만든 후보는 검토에서 통과했으나(포함하면 3/5), 사전 방법인 원문당 한 번 생성의 성공에 넣지 않는다. |
| 사람 검토 시간 | 사용자 측정 기준 총 15분 미만. |

| 미통과 분류 | 건수 | 사례 |
|---|---|---|
| 단순한 숫자 변경 | 1 | 3번 |
| 원문 오독 뒤 다시 만든 후보(일회 생성 아님) | 1 | 4번 |
| 문제의 퀄리티 부족 | 1 | 5번 |

원문 이미지, 모델 출력·자체 검산은 [실행 기록](evidence/candidate_quality_run.md)에, 원본과 후보를 나란히 검토한 자료는 [인쇄용 PDF](evidence/candidate_quality_review_packet.pdf)에 남겼다. 이번 검토는 [SPEC.md](../SPEC.md)의 개발자 1차·강사 2차 제품 검수를 대신하지 않는다.

## 6. 판단과 재도전 조건

- **판정: 원문당 한 번 생성 기준 5건 중 2건 통과(40%) — 3절의 수치 합격선(3건)에 미달.** 4번은 원문 오독 후 다시 만든 후보이므로 일회 생성 성공에 넣지 않았다. 다시 만든 후보까지 포함한 최종 후보 기준으로는 3/5이지만, 두 결과를 하나의 일회 생성 통과 기록으로 취급하지 않는다. 건별 판정 이유와 전체 소요 시간이 없어 시간 제한 준수도 확인할 수 없다. 원문 요소·메커니즘의 실제 계승 여부는 별도로 검증한다.
- **스펙과 온톨로지 반영:** 이번 탐색 결과만으로 수정한 사항은 없다. 원문 요소·메커니즘의 추출 및 후보로의 계승은 [SPEC.md](../SPEC.md)의 AC1·AC3에 별도로 남아 있다. 그 검증 결과가 나올 때 관련 입력·출력 계약과 검토 근거를 [SPEC.md](../SPEC.md) 및 [ontology.yaml](../ontology.yaml)에 반영할지 판단한다.
- **후속 확인·재도전 조건:** 3·5번의 판정 이유를 건별 판정 규칙과 원문 비교 항목으로 나누어 더 구체적으로 기록한다. 재실험에서는 2절의 시간 제한이 포함하는 작업 범위와 3절의 구체 판정 예시를 사전에 확정한다. 정식 평가가 미달이면 오류 유형을 세어 원인을 특정한 뒤 프롬프트나 생성 방식을 수정하고, 수정에 쓰지 않은 별도 사례로 다시 평가한다. 같은 가정의 재도전 기록은 이 파일의 6절 아래에 덧붙인다.

### 재도전 기록 — 2026-10-04

- 문서: [Artist 미적분 Main 재실험](artist_calculus_retest.md). 이 파일의 최종 후보 3/5와 일회 생성 2/5를 구분한 뒤, 성공 조건(1~4절)을 후보 생성 전에 고정하고 원문당 한 번 생성과 문항별 시간을 측정했다.
- 결과: 최초 후보 5건 중 3건(A2·A3·A4)이 건별 규칙 ①~④를 모두 통과해 합격선(3건 이상)에 도달했다. 문항별 생성 시간은 63~132초로 3분 상한을 지켰다. 사람 검토는 수학 문항 제작자 1인 판정이다.
- 남은 한계: 풀이 메커니즘의 실제 계승과 난도 동등성은 확정하지 않았다.
